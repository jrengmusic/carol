# Taste
- Prefers to discuss and align on the approach before implementation ("discuss first") rather than having the agent build things immediately. Confidence: 0.8
- Prioritizes protocol discipline and operational behavior — rules enforcement, communication style, role delegation, and autonomous tool workflows — over tooling/integration plumbing (e.g., CLI subcommands, installer wiring). Confidence: 0.7
- Avoids Anthropic models when using Command Code; wants model choices mapped to the non-Anthropic models actually available on their plan, grounded in the real catalog (e.g., `cmd --list-models`) rather than docs tables or priors. Confidence: 0.9
- Prefers cost-conscious model allocation: cheaper/faster models for routine and discovery roles rather than frontier-tier everywhere; for discovery roles (Librarian/Pathfinder) "any capable model with the most efficient economy" is fine. Actively participates in the role→model mapping but will defer to the agent's efficiency analysis over their own initial picks when the agent demonstrates better cost-efficiency. Confidence: 0.9
- Prefers starting with cheaper, adequate model seats for new setups and iterating later based on hands-on performance ("for starter... we could tweak later, after i have experienced the performance") rather than committing to expensive frontier tiers up front. Confidence: 0.8
- Trusts providers/models they have hands-on experience with (e.g., GLM for auditing) over unproven ones; hesitant to pay more for models they haven't validated with their workflows — especially since their sessions are long and token-hungry. Confidence: 0.8
- Expects claims about tool capability boundaries to be verified against ground truth (authoritative docs and empirical CLI testing) rather than assumed — e.g., probing whether `effort` can be set per agent role at all, or only on the primary session via CLI flags; wants precise answers about what is and isn't supported. Confidence: 0.7
- Prefers deterministic, no-fallback model pinning: the model written on the agent's frontmatter is authoritative and should always be used ("no need fallback for cmd code, counselor model always what written on its frontmatter") — rejects fallback-ladder complexity in favor of a single declared seat. Confidence: 0.7
- Prefers a quiet feed: no `showOutput` on delegated agents, subagent work stays compact, and delegation visibility is treated as a nice-to-have curiosity rather than something to surface verbosely in the UI. Confidence: 0.7
- Prioritizes a strong single source of truth: wants the canonical CAROL structure kept intact as-is with only a thin layer of overrides on top that Command Code reads — explicitly preferring this over full copies/parallel directories ("way better"), because it guarantees everything stays in sync no matter which CLI is used and avoids drift/duplication. Confidence: 0.9
- When porting assets to another tool/CLI, prefers to reuse existing portable assets as-is (e.g., skills and commands that work unchanged, wired via symlinks) rather than translating or duplicating them; only the genuinely incompatible layer (like agent frontmatter model/tool names) gets translated. Confidence: 0.8
- Prefers pragmatic, explicitly-temporary scaffolding decisions (e.g., placing the port script at `~/.carol/bin/carolcmd` "temporarily for now") and minimal initial builds — approving a v1 that is just the port script + bootstrap while deferring optional extras (like a delegation log) to later — over committing to final structure or features up front. Confidence: 0.6
- Wants the primary role adopted automatically by default rather than manually per session — asked for every `cmd` launch to "always" come up as COUNSELOR (default model + memory-role block + SessionStart hook), with other roles as explicit overrides. Prefers zero-friction, always-on defaults over requiring a per-session invocation step. Confidence: 0.8
- Shell tooling must be bash 3.2–compatible (macOS bundled bash): no associative arrays, no heredoc inside command substitution (`$(cat <<'EOF' ...)` mis-parses), and single-quoted strings must avoid bare apostrophes; `read -r -d '' <<'EOF'` is the safe pattern for multi-line string literals. Confidence: 0.7
- Communicates with terse, single-word commands ("push") and expects the agent to recognize the established protocol/context and execute the full workflow autonomously — stage all, write a descriptive commit message, commit, and push — with no confirmation round-trip. Confidence: 0.7
- Prefers role slash commands to be thin, prompt-only stubs kept in the SSOT (`commands/<role>.md`): frontmatter description + "Activate as X. Full role definition is in the X agent." + a MANDATORY acknowledgment line + "wait for ARCHITECT direction, do not start working" — pointing at the full agent file rather than embedding role definitions, and wired into the target tool via symlinks. Confidence: 0.6
- Expects a permissive "allowed by default, except gated by deny" permission model in Command Code: ordinary tool calls should not prompt (wants `permissions.defaultMode` = `auto-accept`), with explicit deny rules and destructive-operation guards as the only gate — matching CAROL's Claude Code behavior rather than `default`/ask mode. Reconfirmed when explicitly demanding the Claude Code destructive-command deny list (git reset --hard / checkout -- / branch -D) also be applied to Command Code via a deterministic PreToolUse hook. Confidence: 0.9
